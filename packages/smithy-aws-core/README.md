# smithy-aws-core

This is the core package that provides AWS specific interfaces for both client and server
tooling generated by Smithy.


## Request compression

HTTP operations with Smithy's `requestCompression` trait use gzip automatically
for buffered payloads of at least 10,240 bytes. Eligible streaming blobs are compressed
without checking their size. Event streams and streams requiring a known length
are excluded. Operations without the trait keep their existing behavior; enabling
compression requires support from the service endpoint.

Seekable input streams remain seekable after compression. SigV4 signing can hash
and rewind them without buffering the entire compressed payload; rewinding
recompresses data as needed. The aiohttp transport checks for an empty body with
a one-byte probe and restores the compressed position instead of scanning to EOF.
Inherently non-seekable streams remain non-seekable,
and the payload-hashing SigV4 signer may buffer them as it does without compression.

AWS client configuration accepts these settings:

- `disable_request_compression=True` disables automatic compression.
- `request_min_compression_size_bytes=0` compresses every eligible buffered request.
- `request_compression_encoding="gzip"` explicitly requests gzip regardless of size.
  An unsupported operation raises an error, as does combining this option with
  `disable_request_compression=True`.

The standard settings also resolve from `AWS_DISABLE_REQUEST_COMPRESSION` and
`AWS_REQUEST_MIN_COMPRESSION_SIZE_BYTES`, or the corresponding lowercase keys in
the shared AWS configuration file. Explicit client settings take precedence.
The explicit encoding option is a client setting only. Zstd is not currently an
encoding supported by Smithy's request-compression trait.
